# AT28C256-15PU — bench checklist

Fitting an AT28C256 EEPROM in the CC784-4's 27C256 ROM socket, running the
patched firmware. Background in `CC784_hardware.md` §2; the fixes themselves
in `CC784_firmware.md` §10–11.

**The T48 needs firmware ≥ `00.1.34`.** Check with any minipro command — the
banner prints it. The factory `00.1.03` silently drives **D6/D7 low during the
program pulse**, so writes come back with two extra zero bits per byte while
reads, chip ID and blank check all look perfect. Symptom: verify fails at the
first byte needing bit 7 or 6 high, e.g. `File=0xF0, Device=0x30`. Fix is
`minipro -F UpdateT48.dat`, taken from an XGpro installer (V12.90 ships
`00.1.34`); minipro will then warn "newer than expected", which is harmless.

**Program the chip before bending any pins.** A lifted pin will not seat
reliably in the T48's ZIF socket afterwards.

**Keep the original M27C256B un-erased** until the EEPROM is proven in the
sign. It is your known-good fallback — just swap it back.

---

## Why two bodges

Only two of the 28 pins differ, and they are the awkward two:

| Pin | Socket supplies | AT28C256 wants | Action |
|---|---|---|---|
| 1 | VPP, hard-wired to 5 V | A14 | lift, wire to A14 |
| 27 | A14 (factory bodge from Z80 pin 4) | `/WE` | lift, wire to VCC |

Leave pin 27 in the socket and board A14 drives `/WE` low on every ROM fetch —
the chip tries to write to itself. That one is not optional.

The other 26 pins match exactly.

---

## 1. Program the chip — 5 min

- [ ] Chip is **not** yet bodged; all pins straight.
- [ ] Seat it in the T48 ZIF, pin 1 toward the lever end, aligned per the
      silkscreen. Close the lever.
- [ ] Run task **`AT28C256-15PU -- program`** (`⇧⌘P → Tasks: Run Task`).
      It builds `cc784nir_patched.bin` first and verifies after writing.
- [ ] Confirm minipro reports **Verification OK** and no ID mismatch.

If it errors on contact, run `minipro -p AT28C256 -z` for a pin check.

---

## 2. Bodge the chip — 15 min

- [ ] **Bend** pin 27 and pin 1 out horizontally. Do not cut them — a bent pin
      keeps the chip reprogrammable and reversible.
- [ ] Solder a short wire from **pin 27 → pin 28 (VCC)**. This ties `/WE` high
      permanently and disables all writes.
- [ ] Solder a wire from **pin 1 → A14**. Two equally good taps:
      - underside pad of ROM **socket pin 27** (carries A14 via the factory
        bodge, and the receptacle is now unused), or
      - **Z80 pin 4** directly.
- [ ] Make the pin 1 joint a solid one. If it works loose the pin floats, A14
      goes indeterminate, and you get intermittent faults rather than a clean
      failure.
- [ ] Sleeve or dress both wires so they cannot short to neighbouring pins.

---

## 3. Check before applying power — 3 min

Meter, chip out of the socket for the first two:

- [ ] Continuity **pin 27 ↔ pin 28**. Must beep.
- [ ] Continuity **pin 27 ↔ pin 1**. Must **not** beep (that would tie A14 to
      VCC and short /WE to an address line).
- [ ] Chip in the socket, both bodged pins clear of their receptacles.
- [ ] Continuity **pin 1 ↔ Z80 pin 4**. Must beep.
- [ ] Continuity **pin 1 ↔ 5 V**. Must **not** beep — confirms pin 1 really is
      clear of the socket's VPP net.
- [ ] Orientation: chip notch matches the socket notch.

---

## 4. Power on — 5 min

The NiCd is removed, so RAM comes up invalid every time. The patched firmware
therefore re-initialises on each boot.

- [ ] Sign powers up, no heat, no smell.
- [ ] Touch the EEPROM after ~30 s. **Warm means `/WE` is still being driven** —
      power off immediately and recheck the pin 27 bodge.
- [ ] The ROM **demo message** scrolls ("COLOR DISPLAY..... ** MAGIC **...").
      That is the expected cold-boot state: store cleared, default sequence
      plays channel 100.

---

## 5. Verify the fixes — 5 min

Serial address is now **1**, not 0 — the patch changes the post-RAM-loss
default. Use `-a 1` from here on.

- [ ] **B1** — ten times in a row, cleanly, no stray bytes, no lock-up:
      ```
      python3 tools/cc784.py -p <port> -a 1 --unsafe id
      ```
      Expect a `B1 01 10 "78409O1702930205" …` frame each time. (`--unsafe`
      is still the flag name; it is what this patch makes safe.)
- [ ] **B5/B7** — the sign answers at address 1 at all, straight from cold.
- [ ] **B2** — clock survives a short `17`:
      ```
      python3 tools/cc784.py -p <port> -a 1 time
      python3 tools/cc784.py -p <port> -a 1 msg 0 "@{5f}"
      python3 tools/cc784.py -p <port> -a 1 raw 17 32
      ```
      The displayed clock must keep advancing after the third command.
- [ ] **B8** — send a 250-character message, then another command right after
      it with no pause. Both should land. Note the 250 bytes take ~8 s on the
      wire at 300 baud regardless; what changed is the dead time *after* the
      ACK, from several seconds down to a fraction of one.
- [ ] **B4 '3'** — `--unsafe dump` now returns the store. Worth capturing: the
      reply layout was never confirmed on hardware because B1 blocked it.

## If something is wrong

| Symptom | Look at |
|---|---|
| Display completely dead | pin 27 still seated, or pin 1 not connected |
| EEPROM warm | `/WE` driven — pin 27 bodge open or shorted to A14 |
| Intermittent garbage, changes on reboot | pin 1 floating — A14 indeterminate |
| Boots but always blank/`FF` | pin 1 stuck high, reading the empty upper 16 K |
| Demo plays, no serial reply | crossover or port, not the chip — try `sniff` |
| minipro ID mismatch | wrong device name, or chip not seated |

Fallback at any point: refit the original M27C256B.

## Reference

- minipro device name: **`AT28C256`** — plain, no `@DIP28` suffix (rejected).
- Image: `src/patched/cc784nir_patched.bin`, 32768 bytes,
  md5 `ae07ad1f8f09854fe37ed02d94d7ed01`.
- Stock image for comparison: `src/stock/cc784nir.bin`,
  md5 `c021af146a50b93a22d13535201b7eaa`.
- Rebuild either: tasks `Build patched ROM` / `Build stock ROM`.
- No image doubling is needed. With pin 1 on real A14, ROM `/CE` only asserts
  when A14 = 0, so the chip never addresses above its own `3FFF`, and the
  firmware ends at `3C20`.
