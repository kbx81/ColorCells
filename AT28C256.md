# AT28C256-15PU — bench checklist

Fitting an AT28C256 EEPROM in the CC784-4's 27C256 ROM socket, running the
patched firmware, writable over the serial link (`CC784_ota.md`). Background
in `CC784_hardware.md` §2; the fixes themselves in `CC784_firmware.md` §10–11.

The image and tasks referenced below are on the **`wip`** branch — `main`
carries `src/stock/` only. The socket wiring and T48 notes apply either way.

**The T48 needs firmware ≥ `00.1.34`.** Check with any minipro command — the
banner prints it. The factory `00.1.03` silently drives **D6/D7 low during the
program pulse**, so writes come back with two extra zero bits per byte while
reads, chip ID and blank check all look perfect. Symptom: verify fails at the
first byte needing bit 7 or 6 high, e.g. `File=0xF0, Device=0x30`. Fix is
`minipro -F UpdateT48.dat`, taken from an XGpro installer (V12.90 ships
`00.1.34`); minipro will then warn "newer than expected", which is harmless.

**Program the chip before bending any pins.** A lifted pin will not seat
reliably in the T48's ZIF socket afterwards.

**Keep the original M27C256B un-erased** until the EEPROM is proven in the
sign. It is your known-good fallback — just swap it back.

---

## Why three bodges and one extra chip

How it works is in `CC784_ota.md`; this is the bench view. The chip must be
writable in circuit, which the 27C256 socket does not provide, and it becomes
two 16 K banks selected by a register the board does not have.

| Pin | Socket supplies | Needed | Action |
|---|---|---|---|
| 27 | A14 (factory bodge from Z80 pin 4) | `/WE` | lift, wire to **Z80 pin 22 (`/WR`)**, 10 k pull-up to 5 V |
| 22 | `/CE` (LS139 pin 12, same net as pin 20) | `/OE` | lift, wire to **Z80 pin 21 (`/RD`)** — unconnected on the board |
| 1 | VPP, hard-wired to 5 V | A14 | lift, wire to **the added '273, pin 2 (Q0)** |

Pin 22 is the one that is easy to miss: the AT28C256 refuses every write while
`/OE` is low, and the socket holds it low whenever the chip is selected.

**The bank register** is a second 74LS273 (or HCT273) piggybacked on U5, the
`8000` control latch: same pinout, so D0–D7, VCC and GND come from the stack.

| '273 pin | Lift? | Wire to |
|---|---|---|
| 3, 4, 7, 8, 13, 14, 17, 18 (D0–D7), 10, 20 | no — soldered to U5's pins | — |
| 11 (clock) | yes | **U4 pin 9** (LS139 `2Y3`, `C000–FFFF`, unused) |
| 1 (`/MR`) | yes | **Z80 pin 26 (`/RESET`)** — bank 0 at every power-up |
| 2 (Q0) | yes | EEPROM pin 1 |
| 5, 6, 9, 12, 15, 16, 19 (Q1–Q7) | yes, leave free | spare outputs (Q1/Q2 reserved for A15/A16 of a bigger chip) |

Do the EEPROM bodges on a machined-pin socket rather than on the chip if you
have one: the chip then stays straight for the T48.

**RAM upgrade (optional, any time):** an AS6C62256 (32 K, 16 K reachable)
in the HY6264 socket. Same two-pin story: lift **pin 26** (CS2 on the 6264,
A13 on the 62256) and wire it to **Z80 pin 3**; lift **pin 1** (NC → A14) and
wire it to **Z80 pin 4** (A14 is always 1 while RAM is selected, so the
chip's upper half is used; GND would work equally, using the lower half).
The firmware detects the chip at boot, so the same image runs on either;
`B4 '1'` reports 15278 bytes instead of 7086.

## 1. Program the chip — 5 min

- [ ] Chip is **not** yet bodged; all pins straight.
- [ ] Seat it in the T48 ZIF, pin 1 toward the lever end, aligned per the
      silkscreen. Close the lever.
- [ ] Run task **`AT28C256-15PU -- program`** (`⇧⌘P → Tasks: Run Task`).
      It builds, runs **`Pack OTA image`** (trailers for both banks) and
      burns `cc784nir_chip.bin`, 32 K, then verifies.
- [ ] Confirm minipro reports **Verification OK** and no ID mismatch.

If it errors on contact, run `minipro -p AT28C256 -z` for a pin check.

---

## 2. Bodge the chips — 30 min

### EEPROM (AT28C256, in the ROM socket)

- [ ] **Bend** pins 1, 22 and 27 out horizontally. Do not cut them.
- [ ] Pin 1 (A14) → '273 pin 2 (Q0).
- [ ] Pin 22 (`/OE`) → Z80 pin 21 (`/RD`).
- [ ] Pin 27 (`/WE`) → Z80 pin 22 (`/WR`), plus 10 k from pin 27 to 5 V.

### Bank register ('273, piggybacked on U5)

- [ ] Bend out pins 1, 2, 5, 6, 9, 11, 12, 15, 16, 19. The ten that stay
      straight (D0–D7, VCC, GND) get soldered to U5's pins.
- [ ] Pin 1 (`/MR`) → Z80 pin 26 (`/RESET`).
- [ ] Pin 11 (clock) → U4 pin 9.
- [ ] Pin 2 (Q0) → EEPROM pin 1 (the same wire as above).
- [ ] Pins 5, 6, 9, 12, 15, 16, 19 (Q1–Q7): free, insulated (Kapton).

### RAM (AS6C62256, in the RAM socket; optional)

- [ ] Remove the factory bodge wire from U13 pin 8 to socket pin 26 (CS2).
      That pad is then free, and pin 1's pad was never connected, so both
      wires can go to the pads with the chip's pins left straight.
- [ ] Pin 26 (A13) → Z80 pin 3. Left floating, the boot hangs at once: the
      stub runs from RAM.
- [ ] Pin 1 (A14) → Z80 pin 4.

### All

- [ ] Sleeve or dress every wire; the lid is metal.

---

## 3. Check before applying power — 5 min

Meter. EEPROM out of its socket for its three checks.

### EEPROM

- [ ] Pin 1 ↔ '273 pin 2, pin 22 ↔ Z80 pin 21, pin 27 ↔ Z80 pin 22: all beep.
- [ ] Pin 27 ↔ 5 V reads ~10 k, not a short.
- [ ] Pins 1, 22, 27 ↔ their socket receptacles: must **not** beep.
- [ ] Chip notch matches the socket notch.

### Bank register

- [ ] Pin 1 ↔ Z80 pin 26 and pin 11 ↔ U4 pin 9: beep.
- [ ] Pin 11 ↔ U5 pin 11: must **not** beep (it would clock with the control latch).
- [ ] Q1–Q7 touch nothing.

### RAM (if upgraded)

- [ ] Pin 26 ↔ Z80 pin 3 and pin 1 ↔ Z80 pin 4: beep.
- [ ] Pin 26 ↔ U13 pin 8: must **not** beep (the old CS2 wire is gone at both ends).

---

## 4. Power on — 5 min

The NiCd is removed, so RAM comes up invalid every time. The patched firmware
therefore re-initialises on each boot.

- [ ] Sign powers up, no heat, no smell.
- [ ] About 1 s of dark before anything shows, longer than stock: the stub
      CRCs the bank before running it.
- [ ] Touch the EEPROM after ~30 s. **Warm means `/WE` is still being driven** —
      power off immediately and recheck the pin 27 bodge.
- [ ] The ROM **demo message** scrolls ("COLOR DISPLAY..... ** MAGIC **...").
      That is the expected cold-boot state: store cleared, default sequence
      plays channel 100.

---

## 5. Verify the fixes — 5 min

Serial address is now **1**, not 0 — the patch changes the post-RAM-loss
default. Use `-a 1` from here on.

- [ ] **B1** — ten times in a row, cleanly, no stray bytes, no lock-up:
      ```
      python3 tools/cc784.py -p <port> -a 1 --unsafe id
      ```
      Expect a `B1 01 10 "78409O1702930205" …` frame each time. (`--unsafe`
      is still the flag name; it is what this patch makes safe.)
- [ ] **B5/B7** — the sign answers at address 1 at all, straight from cold.
- [ ] **B2** — clock survives a short `17`:
      ```
      python3 tools/cc784.py -p <port> -a 1 time
      python3 tools/cc784.py -p <port> -a 1 msg 0 "@{5f}"
      python3 tools/cc784.py -p <port> -a 1 raw 17 32
      ```
      The displayed clock must keep advancing after the third command.
- [ ] **B8** — send a 250-character message, then another command right after
      it with no pause. Both should land. Note the 250 bytes take ~8 s on the
      wire at 300 baud regardless; what changed is the dead time *after* the
      ACK, from several seconds down to a fraction of one.
- [ ] **B4 '3'** — `--unsafe dump` returns the store with a good checksum.
- [ ] **RAM size** — `B4 '1'` says `total 07086` with the 6264, `total 15278`
      with a 62256. Anything else means an address line is not landing.
- [ ] **B11** — `raw 09 30 31 b3 58 59 5a 57` (B3 "XYZW" into empty
      channel 1), then `--unsafe dump`: channel 1 must read `XYZW`, not `YZ`.

---

## 6. First OTA — 10 min

The sign must be on its AC supply: the page writer waits for the mains NMI.
Both banks hold the same app, so the first push writes nothing but a trailer
and the proof is one line of tool output, not the display.

- [ ] Dry run — proves the bank bit flips and both trailers read back (~30 s,
      the tool CRCs all 256 idle-bank pages):
      ```
      uv run tools/cc784_ota.py push src/patched/cc784nir_bank.bin -p <port> -n
      ```
      Expect `running bank 0: {'seq': 1, 'state': 3, …}`, `idle bank 1:
      {'seq': 0, …}` and `0 pages to send`. The same seq for both banks means
      pin 1 never moved: both reads landed in bank 0.
- [ ] Real push: the same command without `-n`. Expect no error from `finish`,
      a 6 s pause, then `OK: running bank 1, {'seq': 2, …}`. The demo keeps
      playing — the image is identical, only the bank changed.
- [ ] Push again: `OK: running bank 0, {'seq': 3, …}`. Both banks have now
      been written and booted.
- [ ] Power-cycle. The sign must come back with the demo (bank 0, newest seq).

ESPHome bridge: `-H <host> -k <key>` instead of `-p <port>`.

## If something is wrong

| Symptom | Look at |
|---|---|
| Display completely dead | pin 27 still seated, or pin 1 not connected |
| EEPROM warm | `/WE` driven — pin 27 bodge open or shorted to A14 |
| Intermittent garbage, changes on reboot | pin 1 floating — A14 indeterminate |
| Boots but always blank/`FF` | pin 1 stuck high, reading the empty upper 16 K |
| Demo plays, no serial reply | crossover or port, not the chip — try `sniff` |
| minipro ID mismatch | wrong device name, or chip not seated |
| `push -n` shows the same seq for both banks | pin 1 not on '273 pin 2, or '273 pin 11 not on U4 pin 9 |
| OTA status 2 (chip timeout) | `/WE` never reaches the chip — pin 27 |
| OTA status 1 (verify failed) | `/OE` still on the socket net — pin 22 |
| `NOT RUNNING THE NEW IMAGE` | the stub rejected the trailer or image CRC; power-cycle and push again |

Fallback at any point: refit the original M27C256B.

## Reference

- minipro device name: **`AT28C256`** — plain, no `@DIP28` suffix (rejected).
- Image: `src/patched/cc784nir_chip.bin`, 32768 bytes, from the `Pack OTA
  image` task (the raw build `cc784nir_patched.bin` has empty trailers and
  boots without a bank check; never burn it).
- Stock image for comparison: `src/stock/cc784nir.bin`,
  md5 `c021af146a50b93a22d13535201b7eaa`.
- Rebuild either: tasks `Build patched ROM` / `Build stock ROM`.
- The chip's two halves are the two banks; the packed image carries the same
  app in both, sequence numbers 1 and 0, so the sign boots bank 0 and has a
  fallback from the first burn. Boot takes ~1 s longer than stock: the stub
  CRCs the bank it is about to run.
