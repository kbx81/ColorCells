# CC784NIR patched firmware

`src/patched/cc784nir.asm`, on the `wip` branch, is the stock reconstruction plus the patches below. `diff src/stock/cc784nir.asm src/patched/cc784nir.asm` is the authoritative changelog: everything outside the patches is kept identical on purpose, with one exception, patch 33, which rewrites every in-range `JP` as a `JR` throughout and so touches 207 stock lines in a mechanical way. The source is fully relocatable (every ROM address is a label), so code is inserted freely; the addresses quoted in the stock notes apply to the stock build only.

What the stock firmware does, and the bugs these patches fix, are in [CC784_firmware.md](CC784_firmware.md); the over-the-air update mechanism the patched build carries is in [CC784_ota.md](CC784_ota.md); fitting the chips it needs is in [CC784_upgrades.md](CC784_upgrades.md).

---

## 1. Memory map

RAM, with the chip-size detection of patch 13:

| Range | Use |
|---|---|
| `4000–40BF` | `FRAMEBUF` — 192-byte column ring (stock: 344 from `4040`); also where the OTA RAM library runs |
| `40C0–42D2` | pointers, `TXBUF`, variables — stock order, 72 dead bytes removed; the configuration block at `42C2–42D1` (patch 35) |
| `42D3–7E2D` | `MSG_STORE`, **15195 bytes** with a 62256; `42D3–5E2D`, **7003**, with the stock 6264 |
| `7E2E–7E4F` | reply stream and packet state (patch 21), display divider and service marks (patch 26), the IR gate's sample and state (patch 35) |
| `7E50–7EEF` | **stack**, 160 bytes (`STACK_SIZE`); `5E50` on the 6264, which mirrors `6000–7FFF` onto `4000–5FFF` |
| `7EF0–7FFB` | packet flag, buffer and parser state |
| `7FF0` | `NMI_SEEN`: FF once a mains NMI has fired since reset |
| `7FFC–7FFF` | boot stub: `NMI_VEC`, `NMI_MAGIC`, `ROM_BANK` |
| `C000` | `BANK_REG`, the added '273 (write-only; bit 0 = EEPROM A14) |

ROM, per 16 K bank ([CC784_ota.md §2](CC784_ota.md#2-rom-layout-each-bank)):

| Range | Use |
|---|---|
| `0000–023F` | boot stub: reset, `0038`, `0066`, bank choice, trial marking, the RAM library. Programmer only |
| `0240–0248` | jump table: `JP app_start`, `JP int_timer`, `JP nmi_entry` |
| `0249–0258` | `ROM_ID` (stock `0048`) |
| `0259–3FBF` | application, then the free space (about 310 bytes) |
| `3FC0–3FFF` | trailer page: magic, sequence number, state, CRCs |

## 2. Patches

1. **Relocate the stack** (fixes B1). The stack is carved off the top of the message store instead of the 64 bytes below `4000`: 128 bytes (`STACK_SIZE`; the measurements are in [CC784_firmware.md §2](CC784_firmware.md#2-execution-architecture-h)). All seven `LD SP` sites use the symbol (reset, `fx_end_of_channel`, `menu_enter`, `key_handler`, the editor, `pkt_process`, `pkt_process_done`). The store's ceiling and the constants `store_init` derives from it move down together, and `store_init` writes the `0xDA` store terminator through `STORE_LIMIT` before zeroing the packet page, since the terminator does not sit inside that page.
2. **Restore the clock** (fixes B2). `pkt_process_done` sets `CLK_RUN=FF` inline, just before its `CALL shift_chain_clear`. This covers every early exit, not just `cmd_17`'s. `cmd_17_set_time` itself cannot be fixed in place: `pkt_next_byte` reads the caller's stack frame (`POP IX/DE/IY`), so no helper can be interposed.
3. **Fix the cursor store** (fixes B6). `LD (STORE_CURSOR),A` → `LD (STORE_CURSOR),HL` in `pkt_insert_text`.
4. **Default address 1 + valid complement** (fixes B5 and B7). `LD A,0 / LD (MY_ADDRESS),A / LD (…INV),A` → `LD HL,FE01 / LD (MY_ADDRESS),HL / NOP / NOP`. `MY_ADDRESS_INV` is `MY_ADDRESS+1`, so one 16-bit store writes both, and `FE` is a genuine complement of `01`.
5. **Shift only the live store** (fixes B8). `LD HL,(STORE_LIMIT)` → `LD HL,(STORE_END)` in `pkt_insert_text`, a two-byte operand change.
6. **Sane defaults after RAM loss: clock at 12:00 AM, empty store, demo.** `init_vars` copies its RAM image from `CLK_RUN` up, so `CLK_H10`…`CLK_PM` (4200–4205) are left alone on purpose, to survive a battery-backed power cycle. Without a battery they are SRAM noise: `clock_tick` only tests for equality, so a garbage second count runs through 255 before wrapping, and `render_clock` shows digits 10–15 as `: ; < = > ?`. The message store is noise too, and `store_repair` faithfully tidies it into 100 channels of garbage that the default sequence then plays. The fix sits in the branch patch 4 already owns — the `MY_ADDRESS`/complement check fails exactly when RAM is fresh — and writes `1 2 0 0 0 0` to the six clock bytes (12:00, seconds 0, AM) and calls `store_clear_all`, so `init_sequence` sees every channel empty and runs the demo, exactly as after a CLR ALL. With a battery and valid RAM the branch is skipped, as before. The clock runs from midnight rather than waiting to be set.
7. **RAM re-layout: 7014-byte store** (+344 over patch 1's layout, +88 over stock). Three changes, each a constant:
   - `STACK_SIZE` 128, sized from the measured 70-byte high-water mark and the ~108-byte constructed worst case.
   - `FRAMEBUF_SIZE` 344 → 192. The column ring only ever holds the 86 visible columns plus the glyph being written (at most 32 more; the renderer waits for the scroll to catch up before the next one) — the four-rows-of-86 size is not needed. TINY mode's output frame lives in `TXBUF`, which is idle while TINY text is displayed (effects are off, and a packet resets everything anyway); the TINY line buffer (`FRAMEBUF_TINY`, 189 bytes from the ring start) fits in the ring.
   - `FRAMEBUF` `4040` → `4000`: the stock stack slot is free once the stack has moved. `cc784_sim.py compare` shows the same frames and replies as the previous layout for every effect, the clock, TINY and the editor.
8. **Compact the variable block: 7086-byte store** (+72). Every byte of the block that nothing reads is gone: ten write-only variables together with the code that fed them, and the unnamed bytes between variables, including `INIT_DATA`'s misaligned second copies of `RX_TIMING` and `rx_st_wait_start`. The order is unchanged and `INIT_DATA` is regenerated as four runs matching the new positions. Three bytes that look dead are not and are kept: `NMI_COUNT+1` is the high byte of a pointer `magic_short_word` reads through, `MSG_STORE-1` takes a space from `store_repair` on every boot (`STORE_GUARD`), and the four bytes after `FB_COL` were what `tiny_scroll_off` scanned through a typo'd pointer, always finding a `0x95` constant, so TINY always pushed the display off first; the scan is gone and that behavior kept. Verified by an emulator census (every RAM byte read or written across the suite, attributed to its symbol), a lockstep diff of every variable against patch 7, and `compare`/`stack`.
9. **Remove the unreachable code.** A static reachability walk over the assembled listing (roots: the three vectors plus every label loaded as a vector or stored as data) leaves five islands nothing can jump to: `keypad_scan` (47 bytes, not referenced at all), `menu_enter` (48 bytes — an "enter your address or `*`" gate that nothing enters; serial `01` goes to `key_handler`), and three orphans behind unconditional jumps (an extra `LD A,0x20` after `clock_emit`, a digit-decrement stub after `editor_key_bgrnd`, a stray `DJNZ/JP` after `cursor_left_8`). Also gone: the raw bytes the disassembly kept as `db` (an unreachable `JP render_loop`, a `RET`, a `JP`, the `AA 55` pair), the five `NOP`s (two of them patch 4's size padding), and `tick6_service`'s re-entrancy guard, which tested `(IX)==AA && (IY)==55` against registers nothing ever points there. About 140 bytes of ROM, zero behavior (`compare` clean).

10. **Boot stub, bank register and A/B layout** ([CC784_ota.md](CC784_ota.md)). `0000–023F` is a stub that picks a bank by trailer and CRC and runs its app through a jump table at `0240` (`STUB_END`); the `0066` NMI goes through a RAM vector guarded by `NMI_MAGIC`. `ROM_ID` sits in the app, and `query_0_romid` uses the label rather than a raw `0048`. Boot is ~1 s slower: the CRC pass.
11. **OTA command set** (`CMD_OTA` = `B5`, `cmd_B5_ota`, [CC784_ota.md §4](CC784_ota.md#4-the-ota-command)): info, page CRCs, begin, write 1–3 pages, finish, reset. Runs the stub's RAM library from `FRAMEBUF`; pages inside the stub refused. ≈ 540 bytes of ROM.
12. **`tx_try_queue` reports busy with carry** (fixes B10).
13. **RAM at the top of the 16 K window; chip size detected at boot.** The board decodes RAM for all of `4000–7FFF`; the 6264 mirrors the upper half. Everything at a fixed address (stack, packet buffers, the stub's bytes) sits under `RAM_TOP` = `8000`, which the 6264 aliases to `5Exx/5Fxx` for free, and `store_init` writes a marker through the mirror to pick `STORE_TOP` (15246 bytes) or `STORE_TOP_8K` (7054). One build for both chips; a 62256 is two wires ([CC784_upgrades.md](CC784_upgrades.md)).

14. **Payload bytes are not keys** (fixes B12): `rx_consume` clears `RX_BYTE` after `pkt_feed_byte`. The OTA handler also blanks the panel before each reply (its RAM library sits in `FRAMEBUF`) and shows a parked UPDATING message from `B5 'B'` to the reboot through the factory test mode.
15. **APPEND seats like DELETE_TEXT** (fixes B11): the extra step back onto an empty channel's marker is gone.
27. **Packets while the demo plays leave the renderer alone.** Patch 24's entry path and `cmd_09` clear `CHAN_LOCK`, and patch 21 no longer restarts the display for a packet that changes nothing under the renderer. Together they left the demo playing from ROM with its lock off after a time-set, a query or a SEQ command, and STOP then opened the editor on the ROM cursor: the first typed key shifted the whole of RAM down by one (`insert_shift` moves everything from the cursor to the store ceiling) and the sign crashed. The lock is now saved with the cursor at entry (`PKT_SAVE_LOCK`) and put back with it. A SEQ command (`PKT_SEQ_CHANGED`), or any packet while the demo plays, recounts the empty channels on the way out and restarts only if the answer flips between the demo and real text, so a sequence that lists a channel with text replaces the demo at once and a sequence of empty channels brings the demo back. Two more patch 21 defects fixed on the way: `is_plain_byte` answered "not plain" for every printable character, so the one-move insert had been moving the store's tail once per byte; and the background transmitter could start on a reply's second segment between the two segment writes, putting the digits before the header, so it now waits for the handoff (`TX_ACTIVE`). Gate: `quiet`.
35. **Configuration block** (+136 bytes, 17 of RAM; +270 with the meters it was developed with). Sixteen bytes just below the message store, battery-backed like the clock beside them: a signature, the address, a flags byte, four spare-line roles, the alert channel, hold time, flash rate, beeper, remote lock, two reserved bytes and an 8-bit sum. The signature and sum are the RAM-validity test at boot, in place of `MY_ADDRESS` against its complement; a failed test applies the defaults (address 1, full brightness, hold 80, flash 13, beeper on, nothing else set) and clears the store and the clock as before, so the first boot of this build starts clean, like a battery change. `B6 index value` writes one byte (the signature, the address and the sum are refused; byte 2 keeps its live bits), `B4 '5'` returns the block and `B4 '6'` the sequence list; the address is still set only by the editor's ADDRESS? dialog, which reseals the block. Brightness is lit time, not passes: the two intensity passes carry bit 0 and bit 1 of every color channel, so dropping a pass drops a bit from every color (the first build did that, and lime turned red). Instead, when dimmed, `latch_row_dim` leaves the row select to the ISR, which lights the row on its next interrupt and parks the rows after 1 or 2 interrupts of the single-tick pass and 3 or 6 of the double-tick pass (a row is lit for 3 and 9 interrupts of those passes, the rest going to the next pass's 86-byte output), so every pixel loses the same share: low is one third, medium two thirds, with no color shift. Lighting on the interrupt grid matters: lit straight from the latch, the row carried a 0 to 128 µs remainder that drifted and pulsed at a few hertz on the sign. Off and mute keep the row dark, at once or at the next message boundary; TINY rows last two ticks and are timed like the double-tick pass. Hold time replaces the `HOLD_FRAMES` constant at its seven sites and flash rate the `FLASH_HALF_PERIOD` compare; the beeper gate sits in `beep_start`; a locked sign drops remote keys in `ir_frame_done` before either consumer sees them. The flags byte: bits 0–1 brightness, 2 muted, 3 mute pending, 4 alert playing, 5 editor open, 6 wrapped; bits 4–7 are live state left out of the sum, and a sequence wrap sets bit 6 until the next message clears it. The roles, the alert channel and the reserved bytes are stored for patch 36. The brightness clock costs the ISR one load and branch per interrupt and the row output a check per pass, which shows up as about ten percent more time to process a packet into a nearly full store (1.07 s to 1.17 s at 15 K; 0.1 s either way when the store is small), so the `ram` gate now waits for DONE like a real host instead of a fixed pause. The OTA commands that read the idle bank (`I`, `C`, `F`) now hold the NMI vector off around the copy (`ota_copy`): the stub vectors the NMI through the jump table of whichever bank is mapped, so an NMI during the copy ran the other image's `nmi_entry` and `clock_tick` against this image's RAM map (the clock variables moved by a byte in this patch); the emulator reports such an NMI as a fault, and `push --all` avoids `C` on a sign still running an older build. Three more things the signs taught: the stack is 160 bytes (a breadcrumb build recorded 110 bytes in use at an interrupt on the sign, against the emulator's 104, and an NMI on top of that overran the old 128 into the TX segment pointers, which is where "the sign streams its memory" came from; a boot-time canary then measured 84–88 bytes during playback, 86 in the editor, 112 during a push's page-CRC commands and 130 while 57 channels of text were loaded into a nearly full store, so the old 128 was overrun by ordinary message loading too; 160 leaves 30 over the deepest measurement and about 10 over the constructed worst case of an NMI at the deepest interrupt moment, and two nights of normal running left 72 and 56 bytes untouched on the two signs); the calibration count moved into the ISR (above); and a parked row costs the ISR nothing (`LIT_LIMIT` is cleared at the park and re-armed by the next `latch_row_dim`). The dimmed interrupt still costs about 5 percent of the CPU, which the renderer could not spare: with a message loaded it stalled for three frames or more 44 times in 75 s at low brightness against 9 at full, each one a visible pause (counted by a renderer heartbeat in the timing query). The IR decoder's per-interrupt handler, about 90 cycles or 6 percent of the CPU even on a sign with no receiver, is now skipped while the decoder is waiting for the line to move (`IR_QUIET`: 1 from `ir_st_leader` on a low line, 3 from `ir_st_idle` or `ir_st_leader2` on a high one, cleared by the ISR when `PORT_SAMPLE` shows the other level), which pays for the dimming. A sign with its receiver unplugged taught the third case: the floating line's edges walked the decoder into `ir_st_leader2`, which waits for a fall that never came, and the handler ran every interrupt until the next boot. One more consequence of lighting from the ISR: a row code left pending must go with the row when `latch_blank` parks it, or a service running late, which starts the next pass at once, would have the ISR light the old code while the next row's 86 bytes are mid-shift, and the panel shows the chain's contents as noise (seen during serial traffic and in the editor). The host's OTA tool waits 8 s for a reply, since every OTA command restarts the display and a sign with an empty store then scans its channels for over 2 s without reading packets. The measuring was done by extra fields in the `B4 '4'` timing query: display ticks merged each second (a service that had not reached the previous tick yet), the longest renderer stall and the count of stalls of three frames or more, and the stack canary's untouched bytes. Once both signs ran with 0 merged ticks and no stalls at any brightness, with the receivers in, those fields, the heartbeat and the canary were removed: 134 bytes of ROM and 9 of RAM back, and the timing query returns its four patch-30 bytes again. They are in the commit history (`a8e9023`). Verified by the `config` gate.
34. **Peephole** (−43 bytes). Found by scanning the listing: thirteen conditional jumps whose target is a lone `RET` become `RET cc`; three `CALL` immediately followed by `RET` become `JP`; two jumps to the very next instruction and one conditional jump that could only ever be taken (a `JR z` right after `JR nz` to the loop) are gone; and nineteen `LD A,0` whose flags nothing reads become `XOR A`, each checked by walking forward to the next flag-setting instruction for a flag consumer. The remaining six `LD A,0` have a consumer in that window and stay.
33. **Short jumps** (−207 bytes). The assembler never shortens a `JP` to a `JR`, and 207 of the app's absolute jumps reach their targets within short range. A script converted them all, let the assembler reject any that drifted out of range as the code shrank, and repeated until stable; the three jump-table entries at `0240` stay `JP`, since the stub enters them at a three-byte stride. A taken `JR` costs two cycles more than a `JP` and a skipped one three fewer, and nothing in the app keeps time by cycle counts: the tick, the scan, the serial engines and the seconds are all hardware-paced, and the bit-time calibration absorbs the slightly longer average acknowledge latency. Verified by every gate and by `compare` against the previous build, which matches in every serial and display phase; the editor and MAGIC phases differ as they do between any two builds of different size, because the remote's frames land on a different interrupt phase and the random seed reads the ROM.
32. **24-hour clock** (+50 bytes). The set-time command's fifth byte takes `H` besides `Y` (AM) and anything else (PM): hours are then 00 to 23, the display keeps the leading zero and drops the AM or PM, and the hours wrap at 24 instead of flipping at 12. The mode lives in bit 1 of `CLK_PM` (`CLK_24H`), next to the digits, so it survives a power cycle with them. The on-sign TIME? prompt still enters 12-hour time and sets 12-hour mode. `cc784.py time24` sets it from the PC.
31. **The clock source follows the add-in board** (+50 bytes). The board puts a 74HC151 in the NMI line, selecting the mains zero-cross or its own 64 Hz from a 32 kHz crystal by the bank register's top bit, Q7 ([CC784_hardware.md](CC784_hardware.md)); bits 0 to 2 stay free for a larger EEPROM. At boot the app waits 75 ms, four mains cycles, for an NMI; none means no mains, so it sets the bit (`BANK_CLOCK_XTAL`) and counts 64 a second (`NMI_PER_SEC_XTAL`). From then on the clock runs on DC, the page writer's NMI sync works and the serial bit time is calibrated, all as on AC. The OTA library in the stub writes the bank register with the bank alone, which drops the bit for the duration of a library call, so `clock_bank` puts it back at every frame end and before each page write, whose sync would otherwise wait on a source that is off. A DC sign without the board sets the bit to no effect and behaves as before: the clock stands and the page writer skips its sync. Gate: `clock`, which runs AC, DC with the board and DC without it, through time setting, rollovers, an OTA page write and a 1200-baud frame.
30. **Serial at 300 to 1200 baud, chosen by the host** (+220 bytes). The bit engines move from the 1302 Hz tick into the interrupt handler itself, so a bit can be a few interrupts long. After a second of silence (`BAUD_IDLE_FRAMES`) the receiver times the next start bit: a frame's `B1` has a one-bit start pulse, 26 interrupts at 300, 13 at 600 and 6.5 at 1200, and that sets the rate for the frame and the session; the transmitter follows, so replies and DONE come back at the host's rate. Every session starts at 300 and falls back to it, so NETCC never sees a difference. The rate is read on the assumption that bit 0 of the first byte is 1, which holds for `B1` and for the bare `01` and `0D`.

    Timing is in fifths of an interrupt. One value, `BAUD_T`, is the 300-baud bit, and the faster rates step the same accumulator 10 or 20 fifths per interrupt (`BAUD_STEP`). An interrupt is 128 µs plus the acknowledge latency, which varies with load, so `BAUD_T` is calibrated rather than assumed: `baud_calibrate` runs from the NMI once a second and takes the low byte of that second's tick6 count, 1280 + s, giving `(1280 + s) / 10`; the count is taken in the ISR where the tick6 mark is made (patch 35), not in the service that handles it, because a service running late merges marks and a shrunken count pulled `BAUD_T` down a few percent on a dimmed sign, which showed as bit-7 errors in 1200-baud replies. A second is accepted only when it agrees with the one before within three ticks and lies within 5 percent of nominal, because a second that lost interrupts to a long DI stretch (an OTA page write, a restart) disagrees with its neighbors; `NMI_COUNT` starts at 0 rather than stock's 176 so whole seconds run from boot. The mains gives the second on AC; the add-in board's 64 Hz gives it on DC once the clock-source patch sets `NMI_PER_SEC`. With no NMI at all the default `BAUD_T` stays, which 1200 tolerates. `B4 '4'` (`cc784.py --unsafe timing`) reports `BAUD_T`, `BAUD_STEP`, the last second's count, and whether an NMI has been seen.

    Because the engines now run inside the interrupt, the latch read-modify-writes in the display and the editor are closed to it (`latch_blank`, `latch_row`) and so is the FIFO reader, and the consumer drains the FIFO once per frame instead of taking one byte, since 62 bytes a second was enough for 300 baud only. The receiver can only look at the line once per interrupt, so a start edge is seen up to one interrupt late and every sample lands on an interrupt boundary: together up to a sixth of a 1200 bit, and long frames pass every time. 2400 is not offered: the same errors are a third of its bit, and on the board, with the period calibrated exactly, most 220-byte frames at 2400 were rejected while short ones passed. A 2400 start bit is refused, so a host trying it gets no answer. Idle cost is a line poll per interrupt, about 6 percent of the CPU. Gate: `baud`, which runs every rate from cold, rate changes after a pause, 1200 over interrupt periods from 126 to 134 µs, 1200 on a DC supply, the 2400 refusal and 300-baud bare bytes; `update` and `push` take a rate.
29. **Factory test mode removed** (−137 bytes). SEQ, then MAGIC, then C in the editor copied a "CURRENT TEST" pattern into `TEST_MSG_BUF`, summed the ROM into four hex digits after it and displayed that until the next key ([CC784_firmware.md §9](CC784_firmware.md#9-on-sign-editor--menu-19ca2a60-m)). On a bank-switched ROM the sum means nothing, and the OTA image carries a CRC. The prompt, the summing loop, the hex formatter and the pattern are gone; MAGIC in the SEQ menu now closes the menu like any other non-digit. `TEST_MODE`, `TEST_MSG_BUF` and the display path stay, because the OTA handler parks its "> FW UPDATE <" message through them.
28. **RAINBOW runs in a random direction.** See patch 19.
26. **Scroll speed by longer rows, not dark ticks.** Stock paces the plain crawl by appending `SCROLL_SPEED` blanked ticks to every 21-tick frame, so the slow settings are also the dim ones: at speed 7 a quarter of every frame is dark. The display now runs on its own divider in `int_timer`: a display tick is 6 interrupts plus `DISP_STRETCH` sevenths of one, carried in `DISP_ACC`, and `frame_speed` sets the stretch to twice the speed for the plain crawl and to zero for effects, TINY and the editor. The 21 ticks of a frame then total the same `126 + 6 × speed` interrupts as stock's frame plus its blank ticks, so every column rate and the FLASH and HOLD timings are stock's, but the rows stay lit the whole time and the two intensity passes keep their 1:2 ratio. The carry pattern is rotated a seventh per frame, since 21 is a multiple of 7, so every row averages the same dwell to within one interrupt. Slower speeds cannot avoid the panel's limits: a 62 Hz column sampling rate means the refresh drops with the column rate, to 46 Hz at speed 7, and single-color text lights every other column, so it blinks at half the column rate. Both dividers only mark `SVC_DUE`; `tick6_service` runs when it is not already running and drains the marks itself, so the engines and the display never nest, which they must not: both read-modify-write the latch shadow and share the RX FIFO. `TICK1_COUNT`, a divider by one, is gone and its byte is the display divider. The TINY frame wait now polls for packets, since a TINY line is seconds of such waits. Gate: `speed` in the emulator, which checks every speed's refresh and column rate, that nothing goes dark and that the seven rows' dwells match.
20. **Clock digits next to the store.** The stub copies its 322-byte library to `4000` at every boot, which runs 130 bytes into the variable block (`RAM_VARS+00..81`). The clock digits sat at `+62..67`, so every power cycle read "0=:39 PM". They now live at `+1F2..1F7`, swapped with six scratch bytes; `CLK_RUN` stays, since the init image rewrites it on every boot. An `ASSERT` keeps the library below `STORE_END`, and `ram` in the emulator checks that a set clock survives a reset.
25. **Restarts stop scanning at the store's end.** `store_repair` runs on every restart and made three passes over the store's whole capacity, 15 K on a 62256, about a second with the panel dark. The passes now stop at the first `DA`; a store that has lost its `DA` still gets the full scan and the repair. Boot is now the CRC pass alone, and a restart after an edit of the playing channel is back on the panel in milliseconds.
24. **Text without a channel goes to channel 0** (fixes B13). The insertion point is derived from the renderer's cursor; while the demo plays that cursor is in ROM and the demo channel's lock (`CHAN_LOCK`) makes every insert a no-op, so the text was ACKed and dropped. A cursor below `MSG_STORE` now clears the lock and seats on channel 0 as `09 30 30 0E` would.
23. **Set-time starts the minute at :00.** `17 hhmm a` carries no seconds and left `CLK_SEC` and the mains-tick count as they were, so the clock came up anywhere inside the minute. Both are zeroed now, and the host tool's `time` command waits for the top of the PC's minute and sends the frame 0.3 s early, which is its wire time.
22. **Typed queries removed** (−270 bytes). The editor hooked `B4` plus a digit typed as keys and answered with its own copies of the three query replies on the serial line, which only a terminal driving the menus could ever see. `editor_query_hook`, `query_dispatch` and the three handlers are gone; packets keep theirs. `QUERIES_ENABLED` is now unused.
21. **Packets are processed by the render loop.** Nothing in the interrupt context reads the message store, so `pkt_process` now runs as a subroutine of the render loop (`pkt_poll`, called at every render step and inside every frame wait) with interrupts on: no `DI`, no stack reset, no restart unless the text being played changed. Its effects:
    - The display keeps scrolling through text loads into other channels, sequence changes, time setting and queries. A restart happens only for an edit of the playing channel, a clear-all, or the first text into an empty sign (the demo stops). The renderer's cursor is saved at entry and put back, shifted by the size change when a lower channel grew or shrank.
    - The sign never goes deaf: the receiver keeps running. A frame that arrives before DONE is parsed in discard mode (`PKT_DISCARD`) and never answered, so its bytes cannot reach the editor as keys.
    - Replies and DONE leave through a background transmitter: two segments with an optional appended sum (`TX_SEG0/1`, fed by `tx_bit_engine`), so a store dump stalls nothing. The `B4` query frames are built over `PKT_BUF`; a query ends its packet.
    - Text goes into the store in one move per run of plain bytes instead of one per byte (`pkt_insert_run`), and DELETE_TEXT moves the store up to its end instead of up to the RAM ceiling: a 240-byte load into a small store is now ~20 ms of processing instead of ~130.
    - `cmd_B5_ota` waits for TX idle and does its own `DI`; OTA packets still park and restart the display.

    The state lives in 32 bytes carved off the store top (`STREAM_AREA`): the store is 15246/7054 bytes. The demo message shrank to one line to pay for the code. Gate: `quiet` in the emulator; `compare` against a tree without this patch reports differences by design.
19. **RAINBOW starts on a random color.** `BC` set the cycle index to 1 and the per-character step advances before it looks up, so every rainbow began on orange. The index now starts at 1–5 from a running 8-bit generator (MAGIC's `RND_SEED`, stirred with the mains and tick counters), so each display cycle begins on a different one of the five colors, on AC and DC alike. Patch 28 adds the direction: bit 7 of `RAINBOW_IDX` (`RAINBOW_REVERSE`), taken from the generator's top bit at the same moment, makes `rainbow_step` count down instead of up, so half the cycles run red, green, lime, yellow, orange.
18. **Trial and confirm.** `F` writes a new image's trailer as TRIAL; the stub rewrites a TRIAL trailer as TRIED before booting it and treats TRIED as invalid, so an image that crashes, hangs or cannot talk is skipped at the next reset. `B5 'K' state seq` rewrites the running bank's trailer: the host confirms (GOOD) once the image answers, or lowers the sequence number to roll back. `NMI_SEEN` (`7FF0`), set by every mains NMI, lets the page writer skip its NMI sync on a DC supply instead of waiting forever; `I` reports it. The stub grew to `0240`.
17. **Label strings parked in the index-space gaps** (+237 bytes). The editor's label lookup is `ATTR_LABEL_TABLE + 2·attr`, so the color-name table must sit 256 bytes after it and the speed labels 128 bytes after the `B0` table; the slots in between (`20–7F`, `D0–EF`) are never indexed. Stock filled the first gap with eleven "TOP OF MSG n" strings that nothing can display (the redraw treats `D0`-class bytes as characters; the real banner is built by `show_top_of_msg`) and the second with zeros. Both now hold live label strings moved from after the tables, and `ds` guards make the assembler enforce the offsets.
16. **DONE handshake.** Immediate mode is "flag bit 7 set"; with bit 0 set as well (`81`) `pkt_process_done` queues a `04` byte, which leaves on the `EI` that makes the sign receptive again, so the sender waits for it instead of guessing at the deaf window of B4. Addressed frames only; NETCC's `80` is unchanged. `B5 'I'` gains a features byte (bit 0) so the host can tell. `cc784.py --done` and `cc784_ota.py` use it; chunked messages and OTA pages then follow each other at wire speed.

## 3. Rejected

- **Always defer processing** (proposed for B3) — *regression on the stock structure*; patch 21 polls from the render loop instead. `main_loop` tests `PKT_READY` only on entry; the `render_loop` render loop never falls back to it. Re-entry happens only via `fx_end_of_channel` or the `BA` wait-for-key spin (`wait_poll`), so a deferred packet waits for the current channel to finish — potentially many seconds after its ACK, during which `rx_idle_byte` refuses every further `B1`. Immediate mode is what makes NETCC responsive. B3 stands as documented, but patch 1 removes its only known trigger: `pkt_process` resets SP on entry and `pkt_process_done` resets it again before jumping to `restart_display`, so the abandoned interrupt frame is harmless as long as the stack is large enough.
- **Send ACK after processing** (proposed for B4) — *regression*. Zero-length frames are ACKed in `pkt_st_cksum` but never set `PKT_READY`, so they would lose their ACK entirely; and a valid ACK would be delayed by the whole insert, which is exactly the interval the sender is trying to measure. Padding after each ACK remains the right mitigation. B8 shrinks the window it has to cover by one to three orders of magnitude — but see the completion byte below, which replaces the padding with a real handshake.

## 5. Rebuilding and testing

```
cd src/patched && sjasmplus cc784nir.asm   # -> cc784nir_patched.bin
uv run tools/cc784_ota.py pack src/patched/cc784nir_patched.bin \
    -o src/patched/cc784nir_bank.bin --t48 src/patched/cc784nir_chip.bin
```

Or the `Build patched ROM` and `Pack OTA image` tasks. The raw build has empty trailers and must not be burned: `cc784nir_chip.bin` is what the T48 burns (task `AT28C256-15PU -- program`) and `cc784nir_bank.bin` what `cc784_ota.py push` sends.

Before any push, run the emulator regression set in [CC784_ota.md §6](CC784_ota.md#6-testing), plus `fuzz` for changes to the stub or the page writer. The emulator itself is described in [CC784_firmware.md §11](CC784_firmware.md#11-rebuilding).
