# CC784NIR patched firmware

`src/patched/cc784nir.asm`, on the `wip` branch, is the stock reconstruction ([src/stock/cc784nir.asm](src/stock/cc784nir.asm)) plus the patches below. The patch list records what differs from stock and why. At the tag `patched-v39`, `diff src/stock/cc784nir.asm src/patched/cc784nir.asm` shows exactly patches 1–39; from there the source is organized for size and the git history is the changelog. The source is fully relocatable (every ROM address is a label); the addresses quoted in the stock notes apply to the stock build only.

What the stock firmware does, and the bugs these patches fix, are in [firmware.md](firmware.md); the over-the-air update mechanism the patched build carries is in [ota.md](ota.md); fitting the chips it needs is in [upgrades.md](upgrades.md).

---

## 1. Memory map

RAM, with the chip-size detection of patch 13:

| Range | Use |
|---|---|
| `4000–40BF` | `FRAMEBUF` — 192-byte column ring (stock: 344 from `4040`); also where the OTA RAM library runs |
| `40C0–42D2` | `TXBUF`; `IMAGE`, the variables with a non-zero boot value (one `LDIR` from `INIT_DATA`); `BOOT_ZERO`, cleared at every boot; scratch buffers; then what survives a reset: `SEQ_LIST`, the boot count (patch 40), the clock, the store limits and the configuration block at `42C2–42D1` (patch 35) |
| `42D3`–`STORE_TOP` | `MSG_STORE`: about 15 K with a 62256, about 7 K with the stock 6264 (`STORE_TOP_8K`); `B4 '1'` reports the exact size |
| `STREAM_AREA`–`7E4F` | reply stream and packet state (patch 21), display divider and service marks (patch 26), the IR gate's sample and state (patch 35), the keypad's mode and state (patch 36), the health counters (patch 40), the status report being sent (patch 41) |
| `7E50–7EEF` | **stack**, `STACK_SIZE` bytes, the lowest `STACK_CANARY` of them laid with a `0x55` canary at boot (patch 40); `5Exx` on the 6264, which mirrors `6000–7FFF` onto `4000–5FFF` |
| `7EF0–7FFB` | packet flag, buffer and parser state |
| `7FF0` | `NMI_SEEN`: FF once a mains NMI has fired since reset |
| `7FFC–7FFF` | boot stub: `NMI_VEC`, `NMI_MAGIC`, `ROM_BANK` |
| `C000` | `BANK_REG`, the added '273 (write-only; bit 0 = EEPROM A14) |

ROM, per 16 K bank ([ota.md §2](ota.md#2-rom-layout-each-bank)):

| Range | Use |
|---|---|
| `0000–023F` | boot stub: reset, `0038`, `0066`, bank choice, trial marking, the RAM library. Programmer only |
| `0240–0248` | jump table: `JP app_start`, `JP int_timer`, `JP nmi_entry` |
| `0249–0258` | `ROM_ID` (stock `0048`) |
| `0259–3FBF` | application, then free space (`FF`) up to the trailer |
| `3FC0–3FFF` | trailer page: magic, sequence number, state, CRCs |

## 2. Patches

1. **Relocate the stack** (fixes B1). The stack is carved off the top of the message store instead of the 64 bytes below `4000`: `STACK_SIZE` bytes (sized in patch 35; the stock measurements are in [firmware.md §3](firmware.md#3-execution-architecture-h)). Every `LD SP` uses the symbol. The store's ceiling and the constants `store_init` derives from it move down together, and `store_init` writes the `0xDA` store terminator through `STORE_LIMIT` before zeroing the packet page, since the terminator does not sit inside that page.
2. **Restore the clock** (fixes B2). `pkt_process_done` sets `CLK_RUN=FF` inline, just before its `CALL shift_chain_clear`. This covers every early exit, not just `cmd_17`'s. `cmd_17_set_time` itself cannot be fixed in place: `pkt_next_byte` reads the caller's stack frame (`POP IX/DE/IY`), so no helper can be interposed.
3. **Fix the cursor store** (fixes B6). `LD (STORE_CURSOR),A` → `LD (STORE_CURSOR),HL` in `pkt_insert_text`.
4. **Default address 1 + valid complement** (fixes B5 and B7). `LD A,0 / LD (MY_ADDRESS),A / LD (…INV),A` → `LD HL,FE01 / LD (MY_ADDRESS),HL / NOP / NOP`. `MY_ADDRESS_INV` is `MY_ADDRESS+1`, so one 16-bit store writes both, and `FE` is a genuine complement of `01`.
5. **Shift only the live store** (fixes B8). `LD HL,(STORE_LIMIT)` → `LD HL,(STORE_END)` in `pkt_insert_text`, a two-byte operand change.
6. **Sane defaults after RAM loss: clock at 12:00 AM, empty store, demo.** `init_vars` copies its RAM image from `CLK_RUN` up, so `CLK_H10`…`CLK_PM` (4200–4205) are left alone on purpose, to survive a battery-backed power cycle. Without a battery they are SRAM noise: `clock_tick` only tests for equality, so a garbage second count runs through 255 before wrapping, and `render_clock` shows digits 10–15 as `: ; < = > ?`. The message store is noise too, and `store_repair` faithfully tidies it into 100 channels of garbage that the default sequence then plays. The fix sits in the branch patch 4 already owns — the `MY_ADDRESS`/complement check fails exactly when RAM is fresh — and writes `1 2 0 0 0 0` to the six clock bytes (12:00, seconds 0, AM) and calls `store_clear_all`, so `init_sequence` sees every channel empty and runs the demo, exactly as after a CLR ALL. With a battery and valid RAM the branch is skipped, as before. The clock runs from midnight rather than waiting to be set.
7. **RAM re-layout.** Three changes, each a constant:
   - The stack is `STACK_SIZE` bytes above the store instead of stock's 64 below `4000` (see patch 35 for its size).
   - `FRAMEBUF_SIZE` 344 → 192. The column ring only ever holds the 86 visible columns plus the glyph being written (at most 32 more, plus the 8-column lead of patch 42) — the four-rows-of-86 size is not needed. TINY mode's output frame lives in `TXBUF`, which is idle while TINY text is displayed (effects are off, and a packet resets everything anyway); the TINY line buffer (`FRAMEBUF_TINY`, 189 bytes from the ring start) fits in the ring.
   - `FRAMEBUF` `4040` → `4000`: the stock stack slot is free once the stack has moved.
8. **Compact the variable block** (+72 bytes of store). Every byte of the block that nothing reads is gone: ten write-only variables together with the code that fed them, and the unnamed bytes between variables, including `INIT_DATA`'s misaligned second copies of `RX_TIMING` and `rx_st_wait_start`. The order is unchanged and `INIT_DATA` is regenerated as four runs matching the new positions. `MSG_STORE-1` looks dead and is kept: it takes a space from `store_repair` on every boot (`STORE_GUARD`). Stock's `tiny_scroll_off` scans the four bytes after `FB_COL` through a typo'd pointer and always finds a `0x95` constant, so TINY always pushes the display off first; the scan is gone and that behavior kept. Verified by an emulator census (every RAM byte read or written across the suite, attributed to its symbol), and `compare`/`stack`.
9. **Remove the unreachable code.** A static reachability walk over the assembled listing (roots: the three vectors plus every label loaded as a vector or stored as data) leaves five islands nothing can jump to: `keypad_scan` (47 bytes, not referenced at all), `menu_enter` (48 bytes — an "enter your address or `*`" gate that nothing enters; serial `01` goes to `key_handler`), and three orphans behind unconditional jumps (an extra `LD A,0x20` after `clock_emit`, a digit-decrement stub after `editor_key_bgrnd`, a stray `DJNZ/JP` after `cursor_left_8`). Also gone: the raw bytes the disassembly kept as `db` (an unreachable `JP render_loop`, a `RET`, a `JP`, the `AA 55` pair), the five `NOP`s (two of them patch 4's size padding), and `tick6_service`'s re-entrancy guard, which tested `(IX)==AA && (IY)==55` against registers nothing ever points there. About 140 bytes of ROM, zero behavior (`compare` clean).

10. **Boot stub, bank register and A/B layout** ([ota.md](ota.md)). `0000–023F` is a stub that picks a bank by trailer and CRC and runs its app through a jump table at `0240` (`STUB_END`); the `0066` NMI goes through a RAM vector guarded by `NMI_MAGIC`. `ROM_ID` sits in the app, and `query_0_romid` uses the label rather than a raw `0048`. Boot is ~1 s slower: the CRC pass.
11. **OTA command set** (`CMD_OTA` = `B5`, `cmd_B5_ota`, [ota.md §4](ota.md#4-the-ota-command)): info, page CRCs, begin, write 1–3 pages, finish, reset. Runs the stub's RAM library from `FRAMEBUF`; pages inside the stub refused. ≈ 540 bytes of ROM.
12. **`tx_try_queue` reports busy with carry** (fixes B10).
13. **RAM at the top of the 16 K window; chip size detected at boot.** The board decodes RAM for all of `4000–7FFF`; the 6264 mirrors the upper half. Everything at a fixed address (stack, packet buffers, the stub's bytes) sits under `RAM_TOP` = `8000`, which the 6264 aliases to `5Exx/5Fxx` for free, and `store_init` writes a marker through the mirror to pick `STORE_TOP` or `STORE_TOP_8K` (store sizes in §1). One build for both chips; a 62256 is two wires ([upgrades.md](upgrades.md)).

14. **Payload bytes are not keys** (fixes B12): `rx_consume` clears `RX_BYTE` after `pkt_feed_byte`. The OTA handler also blanks the panel before each reply (its RAM library sits in `FRAMEBUF`) and shows a parked update message (`>FW ↑<`) from `B5 'B'` to the reboot through the factory test mode.
15. **APPEND seats like DELETE_TEXT** (fixes B11): the extra step back onto an empty channel's marker is gone.
27. **Packets while the demo plays leave the renderer alone.** The renderer's channel lock is saved with the cursor when a packet's processing starts (`PKT_SAVE_LOCK`) and put back with it, so the demo keeps its lock through a time-set, a query or a SEQ command; without it STOP would open the editor on the ROM cursor, and the first typed key would shift all of RAM down by one (`insert_shift` moves everything from the cursor to the store ceiling). A SEQ command (`PKT_SEQ_CHANGED`), or any packet while the demo plays, recounts the empty channels on the way out and restarts only if the answer flips between the demo and real text, so a sequence that lists a channel with text replaces the demo at once and a sequence of empty channels brings the demo back. `is_plain_byte` counts every printable character as plain, so a run of text goes in with one move of the store's tail, and the background transmitter starts only once a reply's segments are handed over (`TX_ACTIVE`). Gate: `quiet`.
44. **Remote decoder clocked by the line's edges** (+171 bytes, 6 of RAM). Stock counts ticks from the end of the leader burst and samples every cell at two fixed points, so the whole frame rides on the interrupt period being 128 µs. The board's period is 128 µs plus the acknowledge latency, 130.2 µs as the baud calibration measures it, and over the 72 ticks of a frame that error reaches 144 µs of a 244 µs budget shared with the tick phase and the receiver's burst stretch, so stock drops about half the remote's frames on this board; the two-frame debounce and the 90 ms repeat turn the losses into keys that need a second press. The decoder trusts rising edges only, the one edge the receiver reports on time (it stretches every burst's end by about 250 µs, so the bursts of a 0 and a following 1 merge). After the leader falls, the start burst must rise 10–23 ticks later; a rise within two ticks of the fall is the leader resuming after a dropout and is waited out again, and any other early rise is a stray burst and is ignored. From the start rise on, every cell is timed from its own edge: a rise in a cell's first three ticks is a 1 and restarts the count, one at ticks 4–2 is a 0, and a cell without a rise is a 1 merged with the 0 before it. Biphase gives the checks in place of the complement sample: a cell without a rise must follow a 0; a cell opening with a rise must follow a 1; and the line must be low through the first two ticks after a 1, since a burst there is either a gap bridged by noise or a 0 faked into a 1 by a burst at its start that ran on into the real one. Rises inside a cell that already has its burst, and rises where neither position fits, are strays and are ignored. A leader counts after 1 ms of quiet instead of 16, since no gap inside a frame but the leader's own exceeds 0.8 ms, so a stray burst shortly before a frame does not cost it. On the consumer side, a key whose second frame was lost registers when its release frame arrives within 0.3 s of the first (`IR_DEBOUNCE_WINDOW`), and two different keys inside one window cancel each other: a frame the decoder rejects costs nothing unless its partner is lost as well, while a mis-decoded frame still cannot type. The same rule covers keys lost to the editor's longer redraws, which would otherwise overwrite an unread code with the release. A seen key is stored with bit 6 set (`IR_KEY`, `IR_DEBOUNCE`), so the idle value 0 is never mistaken for key 0, which in stock types on a single frame. `B4 '4'` grows by four bytes, remote frames by fate (no start after the leader, which is what a stray burst taken for a leader comes to; stray rises ignored; a rise missing after a 1; a burst in a gap), which `cc784.py --unsafe stats` prints. Emulator: every key decodes at interrupt periods from 128 to 132 µs and stretches from 0 to 350 µs with no wrong codes; through random bursts every 20–120 ms, 24 of 27 frames decode (stock's decoder: 8) with none wrong; bursts every 6–9 ms block either decoder. Gates: `keypad`, `config` and the full set, plus the editor session A/B of §6.
43. **No editor during an update** (+12 bytes). STOP on the remote or the wired keypad, or a bare `01` on the serial line, opens the editor from display mode. During an OTA update that would reset the stack, clear `TEST_MODE` (dropping the update message) and echo keys on the serial line, where the host reads them as broken replies and abandons the push with the idle bank half written. All three paths into the editor pass one jump (`key_handler_jr1`), which uses the key up and returns while `TEST_MODE` is set, from `B5 'B'` to the reboot. A push that dies without its reboot therefore leaves the editor shut until the next power cycle; the panel says so meanwhile. Gate: `update`, which presses STOP and sends `01` after `B`.
42. **The crawl keeps columns in hand** (+69 bytes). Stock's LEFT crawl draws a character and then waits until the scroll has caught up completely, so right after every catch-up the renderer has nothing in reserve, and a packet processed at that moment (50 to 65 ms for a 250-byte frame, most of it the interrupt and panel load around a few milliseconds of store work) stops the scroll. The render loop's wait (`crawl_step`) lets the next character be drawn while `CRAWL_LEAD` (8) columns or fewer are still to scroll in, about 130 ms of cover at full speed. Only a plain character qualifies, outside MAGIC, also behind colors (`80`–`93`), which go into the next glyph's column in the same render step; an attribute, the clock's `5F`, the end of the message and every effect still wait for the full catch-up, as do the push-off loops before TINY and the editor (`effect_step`, unchanged), so effects, HALT and TINY see the scroll as stock does. A styled crawl (colors, FLASH, BIG, ITALIC, graphics, the clock, UP, HOLD, HALT) sends the panel the same frames as without the lead, and during a load no panel step takes longer than the normal 16–18 ms. The renderer still pauses while a packet is processed, so patch 40's stall count includes those pauses, which the lead hides.
41. **Status reports** (+97 bytes, 6 of RAM). With `config set status on` (configuration byte 12; off by default, so a host that does not expect them never sees one), the sign sends `B1 addr 03 'S' channel flags sum` at every channel start, and with channel `FF` when the editor opens; the flags byte is `CFG_FLAGS` (bits 0–1 brightness, 2 muted, 3 mute pending, 6 the sequence wrapped to this channel). A report goes out only while no reply is streaming and no frame is arriving, and is dropped otherwise. A frame can still begin while one is on the wire, and a minimal frame is as long as a report, so two guards keep the replies whole: the ACK or NAK of a frame that ends during a report waits in the transmitter's trailing-byte slot (`TX_DONE_PENDING` holds the byte to send: `DONE`, or a deferred ACK or NAK), and `pkt_process` waits for the report to finish before it builds a reply. `cc784.py` takes reports out of the byte stream before its readers see it, so every command works with reports on; `cc784.py watch [SECONDS]` prints them. Gate: `status`.
40. **Health counters in the `B4 '4'` reply** (+154 bytes, 13 of RAM). The timing reply keeps its four bytes and appends fourteen, so a host can poll a sign's health through its dongle: the NMIs per second (60 mains, 64 the add-in board's crystal); a boot count in the free byte beside the clock, which survives a reset and restarts at 1 after RAM loss; stack headroom, the bytes left of a 128-byte `0x55` canary laid at the stack's bottom at every boot; display ticks merged because the last one was still due, for the last second and the worst second; uptime in seconds (3 bytes); renderer stalls, counted when the frame end finds that `pkt_poll` has not run for 3 frames, with the longest gap in frames (the editor, which does not poll, is skipped); frames with a good and a bad checksum; remote frames decoded, and dropped after their leader. Every counter except the boot count lives in the stream area, cleared at boot, so the store's ceiling drops by 13 bytes. Counters wrap at 256. The sequence's step over empty channels (about 50 ms for 99 of them) calls `pkt_poll` for each, so it neither holds up a packet nor counts as a stall. `cc784.py --unsafe stats` prints them (`timing` stays as an alias). Gate: `stats`.
39. **The sequence skips empty channels quickly** (+39 bytes, no RAM: `CHAN_HINT` reuses the unused `MENU_TEXT_PTR`). `chan_select` found a channel by scanning the store from its start, and built the marker by counting up to the channel number, so each step of the sequence cost time in proportion to the channel number. With the default sequence 0–99 and one message loaded, the 99 empty channels took about 1.05 s per loop, during which no packet was processed. Markers sit in the store in channel order, so a channel at or above the one at `CHAN_HINT` is now scanned for from there. The hint needs no updating when the store changes: two marker bytes in a row are always one marker, since every channel ends in `03`, so if the hint no longer points at a marker, or points past the store's `DA` where a shrunken store leaves stale copies, the scan starts from the beginning. The marker is built by dividing by ten. The 99 empty channels now take about 60 ms, and a short message's loop drops from 2.6 s to 1.6 s.
38. **Shared code** (−350 bytes). Duplicated runs are folded into one copy each: `menu_prompt` starts a fresh frame and shows a prompt, and `menu_show_text` takes its string in HL, so `MENU_TEXT_PTR` is unused. `editor_reshow` and `editor_back_if_mark` replace five copies of the channel-marker check. SPEED, GRAPH, COLOR and BGRND set their flag through `editor_set_pending`. Four effects end at `fx_hold_done`. `glyph_addr`, `char_flags` and `glyph_put_next` replace the glyph-address, `CHAR_FLAGS` and digit-drawing sequences. MAGIC's push-off before an effect calls `tiny_scroll_off`, so it pushes `FRAME_COLS/6` spaces: 14 on the CC784 as before, 10 on the CC710. Behavior is unchanged: the full emulator gate set, the CC710 editor prompts and the MAGIC announcement give the same results as before.
37. **CC710 build** (`-DCC710`). The CC710's panel is 59 columns of 74HC595s latched by the port `80` strobe ([hardware.md §11](hardware.md#11-the-cc784-3a-board-h)), on a `CC784-3A` board converted per [§12](hardware.md#12-converting-a-cc784-3a-board-to-a-cc784-4). With `CC710` defined, `FRAME_COLS` is 60 instead of 86 and the output is `cc710_patched.bin`. Everything that depended on the width derives from it: the second frame-buffer row (`FRAMEBUF_ROW1`), the TINY line (`FRAMEBUF_TINY` and its scroll, twice `FRAME_COLS`, pushed out by 20 spaces instead of 28), the push-off before TINY (`FRAME_COLS/6` spaces), the end of the staging frame (`STAGE_END`, which is `STAGE_PTR` itself on the CC784), the empty-stage test (`FRAME_COLS/2`) and the initial `FB_OUT_LEN`. The strobe needs nothing: every row and the chain clear already end with `OUT (PORT_STROBE)`, which the '595s latch on and the '164 panel ignores. The rest, the 100 channels and the CC784's ROM ID included, is the CC784 build's, except the editor's prompts and messages. Those are shortened so that each prompt, with the digits typed after it, fits 59 columns: `MSG nn`, `ADDR? nnn`, `FULL? nn`, `CLR? Y/N`, `TIME? HHMM`, `PROG? nn`, `SEQ? nn` and `MAGIC nn`. The right-aligned messages `INVALID`, `MEM FULL`, `100 LEFT` and `SEQ FULL` are padded to the window as on the CC784. Where the factory CC710 ROM has a wording, the build uses it. Checked in the emulator with text, an UP wipe, TINY and every editor prompt on 60 columns.
36. **Wired keypad; IR moves to bit 4** (+129 bytes, 3 of RAM). Needs the second '244 of [upgrades.md §8](upgrades.md#8-ir-off-the-db9): the decoder reads the receiver on `PORT_IN` bit 4 (`IR_BIT`), leaving bits 0–3 to the keypad, so a sign without that mod has no remote on this build. The decoder's tests and masks change in place, and since its bits now enter `IR_SHIFT` at bit 4, one `RLCA` replaces the four `RRCA` that aligned the code. The keypad takes all seven DB9 signals as on the NET (row select on latch bits 4–6, column code on bits 0–2, key pressed on bit 3 = RX), so serial and keypad never run together. The NET's boot test (a cable with pin 2 shorted to pin 5 means a PC) is not used, because a sign booted without that cable goes deaf to serial and to OTA. Instead, at each frame end (`kp_poll`): in serial mode, 256 frames in a row of the RX line at space, which is a keypad's idle and also an empty socket, switch to keypad mode (4.2 s at the full frame rate; frames stretch at slow scroll speeds); in keypad mode the eight rows are scanned, one row per `DI` so the IR decoder's ticks stay on time, and all eight reading a key is a host's TX idling at mark, which switches back to serial within one frame. `rx_start` ignores the line in keypad mode. A key's code (row × 8 + column) is turned into the remote's key number by a reverse search of `IR_KEY_TABLE` (`CPIR`) and written to `IR_CODE` as the decoder would, so the editor, debounce, repeat, STOP/START and SPACE treat both inputs alike; the release code follows two empty scans (33 ms), which absorbs contact bounce. The table's entry for key 1D, SHIFT, is never read, since SHIFT is caught before the table; it now holds the keypad's SHIFT code, 19. K has two matrix positions, 00 and 1E, and 1E is mapped to 00; 1F is the matrix's empty position. Keypad keys ignore the remote lock. A key pressed while the demo runs an effect waits like the remote's STOP does, since effects pause the frame end. `ir_init`, called when the editor opens, also clears `IR_QUIET`, so a gate left set by the leader wait cannot cost the next key its first frame. Gate: `keypad`, at 16-cycle emulator slices, since at the default 128 a `DI` holds an interrupt up to 16 µs and costs the remote frames the hardware would not lose.
35. **Configuration block** (+136 bytes, 17 of RAM). Sixteen bytes just below the message store, battery-backed like the clock beside them: a signature, the address, a flags byte, four spare-line roles, the alert channel, hold time, flash rate, beeper, remote lock, two reserved bytes and an 8-bit sum. The signature and sum are the RAM-validity test at boot, in place of `MY_ADDRESS` against its complement; a failed test applies the defaults (address 1, full brightness, hold 80, flash 13, beeper on, nothing else set) and clears the store and the clock as before, so the first boot of this build starts clean, like a battery change. `B6 index value` writes one byte (the signature, the address and the sum are refused; byte 2 keeps its live bits), `B4 '5'` returns the block and `B4 '6'` the sequence list; the address is still set only by the editor's ADDRESS? dialog, which reseals the block. Brightness is lit time, not passes: the two intensity passes carry bit 0 and bit 1 of every color channel, so dropping a pass would drop a bit from every color (lime turns red). Instead, when dimmed, `latch_row_dim` leaves the row select to the ISR, which lights the row on its next interrupt and parks the rows after 1 or 2 interrupts of the single-tick pass and 3 or 6 of the double-tick pass (a row is lit for 3 and 9 interrupts of those passes, the rest going to the next pass's 86-byte output), so every pixel loses the same share: low is one third, medium two thirds, with no color shift. Lighting on the interrupt grid matters: lit straight from the latch, the row carries a 0 to 128 µs remainder that drifts and pulses at a few hertz. Off and mute keep the row dark, at once or at the next message boundary; TINY rows last two ticks and are timed like the double-tick pass. Hold time replaces the `HOLD_FRAMES` constant at its seven sites and flash rate the `FLASH_HALF_PERIOD` compare; the beeper gate sits in `beep_start`; a locked sign drops remote keys in `ir_frame_done` before either consumer sees them. The flags byte: bits 0–1 brightness, 2 muted, 3 mute pending, 4 alert playing, 5 editor open, 6 wrapped; bits 4–7 are live state left out of the sum, and a sequence wrap sets bit 6 until the next message clears it. The roles, the alert channel and the reserved bytes are stored for a later patch. The brightness clock costs the ISR one load and branch per interrupt and the row output a check per pass: about ten percent more time to process a packet into a nearly full store (1.07 s to 1.17 s at 15 K; 0.1 s either way when the store is small), so the `ram` gate waits for DONE, as a real host does. The OTA commands that read the idle bank (`I`, `C`, `F`) hold the NMI vector off around the copy (`ota_copy`): the stub vectors the NMI through the jump table of whichever bank is mapped, so an NMI during the copy would run the other image's `nmi_entry` and `clock_tick` against this image's RAM map; the emulator reports such an NMI as a fault, and `push --all` avoids `C` on a sign running a build without `ota_copy`. The stack is 160 bytes. Measured on the signs: 84–88 bytes during playback, 86 in the editor, 112 during a push's page-CRC commands and 130 while 57 channels of text load into a nearly full store; normal running leaves 56–72 bytes untouched. 160 leaves 30 over the deepest measurement and about 10 over the constructed worst case of an NMI at the deepest interrupt moment; an overrun reaches the TX segment pointers and the sign streams its memory on TX. A parked row costs the ISR nothing (`LIT_LIMIT` is cleared at the park and re-armed by the next `latch_row_dim`). The dimmed interrupt costs about 5 percent of the CPU, more than the renderer can spare with a message loaded (it pauses visibly at low brightness), so the IR decoder's per-interrupt handler, about 90 cycles or 6 percent of the CPU even on a sign with no receiver, is skipped while the decoder is waiting for the line to move (`IR_QUIET`: 1 from `ir_st_leader` on a low line, `PORT_IR | 1` from `ir_st_idle` or `ir_st_leader2` on a high one, cleared by the ISR when `PORT_SAMPLE` shows the other level). The third case covers an unplugged receiver, whose floating line can walk the decoder into `ir_st_leader2` to wait for a fall that never comes. A row code left pending goes with the row when `latch_blank` parks it; otherwise a service running late, which starts the next pass at once, would have the ISR light the old code while the next row's 86 bytes are mid-shift, and the panel shows the chain's contents as noise. The host's OTA tool waits 8 s for a reply, since every OTA command restarts the display and a sign with an empty store then scans its channels for over 2 s without reading packets. Verified by the `config` gate.
34. **Peephole** (−46 bytes). Thirteen conditional jumps whose target is a lone `RET` become `RET cc`; three `CALL` immediately followed by `RET` become `JP`; three jumps to the very next instruction and one conditional jump that could only ever be taken (a `JR z` right after `JR nz` to the loop) are gone; and nineteen `LD A,0` whose flags nothing reads become `XOR A`, each checked by walking forward to the next flag-setting instruction for a flag consumer. The remaining six `LD A,0` have a consumer in that window and stay.
33. **Short jumps** (−217 bytes). The assembler never shortens a `JP` to a `JR`, so the 217 absolute jumps in the app that reach their targets within short range are written as `JR`; the three jump-table entries at `0240` stay `JP`, since the stub enters them at a three-byte stride. A taken `JR` costs two cycles more than a `JP` and a skipped one three fewer, and nothing in the app keeps time by cycle counts: the tick, the scan, the serial engines and the seconds are all hardware-paced, and the bit-time calibration absorbs the slightly longer average acknowledge latency. Verified by every gate and by `compare` against a build without this patch, which matches in every serial and display phase; the editor and MAGIC phases differ as they do between any two builds of different size, because the remote's frames land on a different interrupt phase and the random seed reads the ROM.
32. **24-hour clock** (+50 bytes). The set-time command's fifth byte takes `H` besides `Y` (AM) and anything else (PM): hours are then 00 to 23, the display keeps the leading zero and drops the AM or PM, and the hours wrap at 24 instead of flipping at 12. The mode lives in bit 1 of `CLK_PM` (`CLK_24H`), next to the digits, so it survives a power cycle with them. The on-sign TIME? prompt still enters 12-hour time and sets 12-hour mode. `cc784.py time24` sets it from the PC.
31. **The clock source follows the add-in board** (+50 bytes). The board puts a 74HC151 in the NMI line, selecting the mains zero-cross or its own 64 Hz from a 32 kHz crystal by the bank register's top bit, Q7 ([hardware.md](hardware.md)); bits 0 to 2 stay free for a larger EEPROM. At boot the app waits 75 ms, four mains cycles, for an NMI; none means no mains, so it sets the bit (`BANK_CLOCK_XTAL`) and counts 64 a second (`NMI_PER_SEC_XTAL`). From then on the clock runs on DC, the page writer's NMI sync works and the serial bit time is calibrated, all as on AC. The OTA library in the stub writes the bank register with the bank alone, which drops the bit for the duration of a library call, so `clock_bank` puts it back at every frame end and before each page write, whose sync would otherwise wait on a source that is off. A DC sign without the board sets the bit to no effect and behaves as before: the clock stands and the page writer skips its sync. Gate: `clock`, which runs AC, DC with the board and DC without it, through time setting, rollovers, an OTA page write and a 1200-baud frame.
30. **Serial at 300 to 1200 baud, chosen by the host** (+220 bytes). The bit engines move from the 1302 Hz tick into the interrupt handler itself, so a bit can be a few interrupts long. After a second of silence (`BAUD_IDLE_FRAMES`) the receiver times the next start bit: a frame's `B1` has a one-bit start pulse, 26 interrupts at 300, 13 at 600 and 6.5 at 1200, and that sets the rate for the frame and the session; the transmitter follows, so replies and DONE come back at the host's rate. Every session starts at 300 and falls back to it, so NETCC never sees a difference. The rate is read on the assumption that bit 0 of the first byte is 1, which holds for `B1` and for the bare `01` and `0D`.

    Timing is in fifths of an interrupt. One value, `BAUD_T`, is the 300-baud bit, and the faster rates step the same accumulator 10 or 20 fifths per interrupt (`BAUD_STEP`). An interrupt is 128 µs plus the acknowledge latency, which varies with load, so `BAUD_T` is calibrated rather than assumed: `baud_calibrate` runs from the NMI once a second and takes the low byte of that second's tick6 count, 1280 + s, giving `(1280 + s) / 10`; the count is taken in the ISR where the tick6 mark is made (patch 35), not in the service that handles it, because a service running late merges marks, and the shrunken count would pull `BAUD_T` down a few percent (bit-7 errors in 1200-baud replies on a dimmed sign). A second is accepted only when it agrees with the one before within three ticks and lies within 5 percent of nominal, because a second that lost interrupts to a long DI stretch (an OTA page write, a restart) disagrees with its neighbors; `NMI_COUNT` starts at 0 rather than stock's 176 so whole seconds run from boot. The mains gives the second on AC; the add-in board's 64 Hz gives it on DC once the clock-source patch sets `NMI_PER_SEC`. With no NMI at all the default `BAUD_T` stays, which 1200 tolerates. `B4 '4'` (`cc784.py --unsafe stats`) reports `BAUD_T`, `BAUD_STEP`, the last second's count and whether an NMI has been seen, followed by patch 40's counters.

    Because the engines now run inside the interrupt, the latch read-modify-writes in the display and the editor are closed to it (`latch_blank`, `latch_row`) and so is the FIFO reader, and the consumer drains the FIFO once per frame instead of taking one byte, since 62 bytes a second was enough for 300 baud only. The receiver can only look at the line once per interrupt, so a start edge is seen up to one interrupt late and every sample lands on an interrupt boundary: together up to a sixth of a 1200 bit, and long frames pass every time. 2400 is not offered: the same errors are a third of its bit, and on the board, with the period calibrated exactly, most 220-byte frames at 2400 were rejected while short ones passed. A 2400 start bit is refused, so a host trying it gets no answer. Idle cost is a line poll per interrupt, about 6 percent of the CPU. Gate: `baud`, which runs every rate from cold, rate changes after a pause, 1200 over interrupt periods from 126 to 134 µs, 1200 on a DC supply, the 2400 refusal and 300-baud bare bytes; `update` and `push` take a rate.
29. **Factory test mode removed** (−137 bytes). SEQ, then MAGIC, then C in the editor copied a "CURRENT TEST" pattern into `TEST_MSG_BUF`, summed the ROM into four hex digits after it and displayed that until the next key ([firmware.md §10](firmware.md#10-on-sign-editor--menu-19ca2a60-m)). On a bank-switched ROM the sum means nothing, and the OTA image carries a CRC. The prompt, the summing loop, the hex formatter and the pattern are gone; MAGIC in the SEQ menu now closes the menu like any other non-digit. `TEST_MODE`, `TEST_MSG_BUF` and the display path stay, because the OTA handler parks its `>FW ↑<` message (the `^` byte is the up-arrow glyph) through them.
28. **RAINBOW runs in a random direction.** See patch 19.
26. **Scroll speed by longer rows, not dark ticks.** Stock paces the plain crawl by appending `SCROLL_SPEED` blanked ticks to every 21-tick frame, so the slow settings are also the dim ones: at speed 7 a quarter of every frame is dark. The display now runs on its own divider in `int_timer`: a display tick is 6 interrupts plus `DISP_STRETCH` sevenths of one, carried in `DISP_ACC`, and `frame_speed` sets the stretch to twice the speed for the plain crawl and to zero for effects, TINY and the editor. The 21 ticks of a frame then total the same `126 + 6 × speed` interrupts as stock's frame plus its blank ticks, so every column rate and the FLASH and HOLD timings are stock's, but the rows stay lit the whole time and the two intensity passes keep their 1:2 ratio. The carry pattern is rotated a seventh per frame, since 21 is a multiple of 7, so every row averages the same dwell to within one interrupt. Slower speeds cannot avoid the panel's limits: a 62 Hz column sampling rate means the refresh drops with the column rate, to 46 Hz at speed 7, and single-color text lights every other column, so it blinks at half the column rate. Both dividers only mark `SVC_DUE`; `tick6_service` runs when it is not already running and drains the marks itself, so the engines and the display never nest, which they must not: both read-modify-write the latch shadow and share the RX FIFO. `TICK1_COUNT`, a divider by one, is gone and its byte is the display divider. The TINY frame wait now polls for packets, since a TINY line is seconds of such waits. Gate: `speed` in the emulator, which checks every speed's refresh and column rate, that nothing goes dark and that the seven rows' dwells match.
20. **Clock digits next to the store.** The stub copies its 322-byte library to `4000` at every boot, which runs 130 bytes into the variable block (`RAM_VARS+00..81`). At stock's `+62..67` the clock digits are overwritten at every power cycle ("0=:39 PM"). They now live at `+1F2..1F7`, swapped with six scratch bytes; `CLK_RUN` stays, since the init image rewrites it on every boot. An `ASSERT` keeps the library below `STORE_END`, and `ram` in the emulator checks that a set clock survives a reset.
25. **Restarts stop scanning at the store's end.** `store_repair` runs on every restart and made three passes over the store's whole capacity, 15 K on a 62256, about a second with the panel dark. The passes now stop at the first `DA`; a store that has lost its `DA` still gets the full scan and the repair. Boot is now the CRC pass alone, and a restart after an edit of the playing channel is back on the panel in milliseconds.
24. **Text without a channel goes to channel 0** (fixes B13). The insertion point is derived from the renderer's cursor; while the demo plays that cursor is in ROM and the demo channel's lock (`CHAN_LOCK`) makes every insert a no-op, so the text was ACKed and dropped. A cursor below `MSG_STORE` now clears the lock and seats on channel 0 as `09 30 30 0E` would.
23. **Set-time starts the minute at :00.** `17 hhmm a` carries no seconds and left `CLK_SEC` and the mains-tick count as they were, so the clock came up anywhere inside the minute. Both are zeroed now, and the host tool's `time` command waits for the top of the PC's minute and sends the frame 0.3 s early, which is its wire time.
22. **Typed queries removed** (−270 bytes). The editor hooked `B4` plus a digit typed as keys and answered with its own copies of the three query replies on the serial line, which only a terminal driving the menus could ever see. `editor_query_hook`, `query_dispatch` and the three handlers are gone; packets keep theirs. `QUERIES_ENABLED` is now unused.
21. **Packets are processed by the render loop.** Nothing in the interrupt context reads the message store, so `pkt_process` now runs as a subroutine of the render loop (`pkt_poll`, called at every render step and inside every frame wait) with interrupts on: no `DI`, no stack reset, no restart unless the text being played changed. Its effects:
    - The display keeps scrolling through text loads into other channels, sequence changes, time setting and queries. A restart happens only for an edit of the playing channel, a clear-all, or the first text into an empty sign (the demo stops). The renderer's cursor is saved at entry and put back, shifted by the size change when a lower channel grew or shrank.
    - The sign never goes deaf: the receiver keeps running. A frame that arrives before DONE is parsed in discard mode (`PKT_DISCARD`) and never answered, so its bytes cannot reach the editor as keys.
    - Replies and DONE leave through a background transmitter: two segments with an optional appended sum (`TX_SEG0/1`, fed by `tx_bit_engine`), so a store dump stalls nothing. The `B4` query frames are built over `PKT_BUF`; a query ends its packet.
    - Text goes into the store in one move per run of plain bytes instead of one per byte (`pkt_insert_run`), and DELETE_TEXT moves the store up to its end instead of up to the RAM ceiling: a 240-byte load into a small store is now ~20 ms of processing instead of ~130.
    - `cmd_B5_ota` waits for TX idle and does its own `DI`; OTA packets still park and restart the display.

    The state lives in the stream area carved off the store top (`STREAM_AREA`, §1). The demo message is one line. Gate: `quiet` in the emulator; `compare` against a tree without this patch reports differences by design.
19. **RAINBOW starts on a random color.** `BC` set the cycle index to 1 and the per-character step advances before it looks up, so every rainbow began on orange. The index now starts at 1–5 from a running 8-bit generator (MAGIC's `RND_SEED`, stirred with the mains and tick counters), so each display cycle begins on a different one of the five colors, on AC and DC alike. Patch 28 adds the direction: bit 7 of `RAINBOW_IDX` (`RAINBOW_REVERSE`), taken from the generator's top bit at the same moment, makes `rainbow_step` count down instead of up, so half the cycles run red, green, lime, yellow, orange.
18. **Trial and confirm.** `F` writes a new image's trailer as TRIAL; the stub rewrites a TRIAL trailer as TRIED before booting it and treats TRIED as invalid, so an image that crashes, hangs or cannot talk is skipped at the next reset. `B5 'K' state seq` rewrites the running bank's trailer: the host confirms (GOOD) once the image answers, or lowers the sequence number to roll back. `NMI_SEEN` (`7FF0`), set by every mains NMI, lets the page writer skip its NMI sync on a DC supply instead of waiting forever; `I` reports it. The stub occupies `0000–023F`.
17. **Label strings parked in the index-space gaps** (+237 bytes). The editor's label lookup is `ATTR_LABEL_TABLE + 2·attr`, so the color-name table must sit 256 bytes after it and the speed labels 128 bytes after the `B0` table; the slots in between (`20–7F`, `D0–EF`) are never indexed. Stock filled the first gap with eleven "TOP OF MSG n" strings that nothing can display (the redraw treats `D0`-class bytes as characters; the real banner is built by `show_top_of_msg`) and the second with zeros. Both now hold live label strings moved from after the tables, and `ds` guards make the assembler enforce the offsets.
16. **DONE handshake.** Immediate mode is "flag bit 7 set"; with bit 0 set as well (`81`) `pkt_process_done` queues a `04` byte, which leaves on the `EI` that makes the sign receptive again, so the sender waits for it instead of guessing at the deaf window of B4. Addressed frames only; NETCC's `80` is unchanged. `B5 'I'` gains a features byte (bit 0) so the host can tell. `cc784.py --done` and `cc784_ota.py` use it; chunked messages and OTA pages then follow each other at wire speed.

## 3. Rejected

- **Always defer processing** (proposed for B3) — *regression on the stock structure*; patch 21 polls from the render loop instead. `main_loop` tests `PKT_READY` only on entry; the `render_loop` render loop never falls back to it. Re-entry happens only via `fx_end_of_channel` or the `BA` wait-for-key spin (`wait_poll`), so a deferred packet waits for the current channel to finish — potentially many seconds after its ACK, during which `rx_idle_byte` refuses every further `B1`. Immediate mode is what makes NETCC responsive. Patch 21 removes the hazard: packets are processed from the render loop, not inside `tick6_service`.
- **Send ACK after processing** (proposed for B4) — *regression*. Zero-length frames are ACKed in `pkt_st_cksum` but never set `PKT_READY`, so they would lose their ACK entirely; and a valid ACK would be delayed by the whole insert, which is exactly the interval the sender is trying to measure. B8 shrinks the window a sender must pad after each ACK by one to three orders of magnitude, and patch 16's DONE byte replaces the padding with a real handshake.

cd src/patched && sjasmplus cc784nir.asm   # -> cc784nir_patched.bin
uv run tools/cc784_ota.py pack src/patched/cc784nir_patched.bin \
    -o src/patched/cc784nir_bank.bin --t48 src/patched/cc784nir_chip.bin

Or the `Build patched ROM` and `Pack OTA image` tasks. The CC710 build is `sjasmplus -DCC710 cc784nir.asm` (`cc710_patched.bin`, packed to `cc710_bank.bin` and `cc710_chip.bin`), or the tasks of the same names with `(CC710)` appended. ## 6. Size refactor after `patched-v39`

From the tag `patched-v39` on, the source is organized for size rather than for a small diff against stock. What a reader of the source needs to know:

- **Font:** glyphs are stored at their own widths. `FONT_WIDTH` holds each glyph's width and `FONT_BLOCK` the address of every eighth glyph; `glyph_addr` adds up to seven widths and sets `GLYPH_WIDTH`. `glyph_lookup` always copies the glyph into a buffer before styling, since bold and BIG read one column past the end.
- **Character classes:** `CHAR_FLAGS` is two bits per character (64 bytes) behind `char_flags`, which returns Z for printable text and CY for an invalid byte.
- **Keys and labels:** the two upper-case charset tables are gone; `getkey_lookup` folds a–z up when exactly one of SHIFT and CAPS is on. The editor's labels are one keyed list, `LABELS`, searched by `redraw_show_label`.
- **Dispatch:** `CALL dispatch` followed by a table of `DKEY key, target` entries replaces the CP/JP ladders in the editor, the packet loop, the effects and the channel prompt. sjasmplus substitutes macro parameter names inside identifiers, hence the parameter names `zk`/`zt`.
- **RAM:** see the map in §1. A variable that must survive a reset sits outside `BOOT_ZERO`. Moving one of those (`SEQ_LIST`, the clock, the store limits, the configuration block) means the first boot after an OTA update reads it from its old address: the boot checks put defaults back where they can, otherwise the value is lost.
- **Short jumps:** beyond patch 33, far jumps reach their targets through an existing unconditional `JP` to the same target within range, labelled `<target>_jrN`.
- **Rejected:** a single-entry IR decoder (63 bytes smaller) took about 235 cycles per interrupt against about 90, so the next interrupt nested inside it and keys were lost. Per-interrupt handlers stay short.

Verification for changes of this kind: the full emulator set ([ota.md §6](ota.md#6-testing)); `compare` is only meaningful in its boot and `B4` phases, because the effects, editor and MAGIC phases diverge between any two builds of different speed. For the editor, compare the steady panel frame after each remote key between the two builds instead.
